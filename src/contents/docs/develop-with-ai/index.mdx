Use AI to write, fix, and operate flows, from the Kestra UI or from your own coding agent.

This section is for anyone who builds or runs flows. The AI here helps you do the work and never runs as part of a flow. To call a model, run an AI agent, or expose flows to external agents at runtime, see [AI Orchestration](../ai-orchestration/index.mdx).

None of this is required. Every flow you can generate with AI, you can also write in YAML or build in the No-Code editor.

## Choose a tool

Start from where you already work:

| Where you work | Use | What it gives you |
| --- | --- | --- |
| The Kestra UI | [AI Copilot](./01.ai-copilot/index.md) | Build and edit flows from a prompt, diagnose failed executions, and run approved multi-step plans |
| A coding agent in your terminal or editor, such as Claude Code, Cursor, Codex, or Windsurf | [Docs MCP server](./02.kestra-mcp-resources/index.md) and [Agent Skills](./03.agent-skills/index.md) | Your agent writes, validates, and deploys flows next to the rest of your codebase |
| Scripts and CI | [`kestractl`](../kestra-cli/kestractl/index.md) | Deterministic flow, execution, and namespace operations with no AI involved |
| Your own AI tool or integration | [Docs for Agents](./04.docs-for-agents/index.md) | Every machine-readable Kestra resource: `llms.txt`, Markdown docs, plugin schemas, and OpenAPI specs |

## Use your own coding agent

If your flows live in Git next to application code, you can stay in your coding agent. Three pieces work together, and each covers a different gap:

- **[Docs MCP server](./02.kestra-mcp-resources/index.md) for context.** A hosted [Model Context Protocol](https://modelcontextprotocol.io/) endpoint that gives your agent live task schemas for all <PluginCount client:idle /> plugins, the blueprints library, and documentation search. Without it, an agent guesses plugin properties from stale training data.
- **[Agent Skills](./03.agent-skills/index.md) for know-how.** `SKILL.md` files that teach your agent to write valid flows, harden them for production, operate an environment, and migrate from Airflow or to Kestra 2.0. Skills carry the guardrails: no invented task types, no hardcoded secrets, validate before deploying.
- **[`kestractl`](../kestra-cli/kestractl/index.md) to act.** The Kestra CLI that the agent calls to validate, deploy, and run flows on your instance. Without it, the agent can write flows but can't deploy them.

To set up all three, connect the [Docs MCP server](./02.kestra-mcp-resources/index.md#connect-the-mcp-server), [install the skills](./03.agent-skills/index.md#setup), and [configure `kestractl`](../kestra-cli/kestractl/index.md). The [Agent Skills examples](./03.agent-skills/index.md#example-workflows) show a single prompt that writes, validates, and deploys a flow. For a step-by-step setup in Claude Code, follow the [Claude Code Quickstart](../claude-code-quickstart/index.mdx).
