Kestra 2.1.0 requires no flow rewrites. The changes below affect API clients, CLI scripts, role definitions, and server configuration, so review them before upgrading from 2.0.

:::alert{type="warning"}
**Back up your database first.** The asset relations migration (Enterprise Edition) moves existing lineage into a new store and drops the old tables. Take a full backup of the repository database before upgrading. If the queue runs in a [dedicated database](../../configuration/02.runtime-and-storage/index.md#dedicated-queue-database), back up both.
:::

## What changed in 2.1.0

| Change | Who is affected | What to do |
|---|---|---|
| [Concurrency limit API](./concurrency-limit-api) | API clients and scripts that read or update concurrency limits | Switch to `PUT /api/v1/{tenant}/concurrency-limit` with the scope in the body, and page through search results. |
| [`SYSTEM_SETTINGS` and `TENANT_SETTINGS` removed](./settings-permissions-removed) (EE) | Role definitions in the API, `kestractl`, or Terraform | Remove both permissions. Requests that include them fail with a 422. Stored roles need no change. |
| [Server CLI commands deprecated](./server-cli-commands-deprecated) | Scripts that call `kestra flow`, `kestra namespace kv`, `kestra auths`, `kestra tenants`, or `kestra workers` commands | Move to the `kestractl` equivalents. Deprecated commands now print a deprecation line to stdout. |
| [Queue configuration keys](./queue-backend-configuration) (EE) | Kafka, Redis, and AMQP deployments | Move settings under `kestra.queue.<type>`. The old keys still work but log a deprecation warning. |
| [POST-only logout](./sso-logout-post-only) (EE) | SSO deployments, configurations with `get-allowed: true`, and direct links to `/logout` | Register `<your Kestra URL>/ui` as the post-logout redirect URI in your identity provider and remove `get-allowed` overrides. `GET /logout` now returns 405. |
| [Asset relations](./asset-relations) (EE) | Users of the lineage-events API, `kestractl assets lineage-events`, or `PurgeAssets` lineage options | Read lineage from the relations API instead. Flows with an invalid asset `id` are now rejected on save. |
