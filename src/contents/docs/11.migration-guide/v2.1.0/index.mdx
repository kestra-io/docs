Kestra 2.1.0 requires no flow rewrites, except asset triggers and declarations that match dbt assets on the `Table` type, and flow outputs typed with an input-only type such as `SELECT`. The changes below affect API clients, CLI scripts, role definitions, and server configuration, so review them before upgrading from 2.0.

:::alert{type="warning"}
**Back up your database first.** The asset relations migration (Enterprise Edition) moves existing lineage into a new store and drops the old tables. Take a full backup of the repository database before upgrading. If the queue runs in a [dedicated database](../../configuration/02.runtime-and-storage/index.md#dedicated-queue-database), back up both.
:::

## What changed in 2.1.0

| Change | Who is affected | What to do |
|---|---|---|
| [Concurrency limit API](./concurrency-limit-api) | API clients and scripts that read or update concurrency limits | Switch to `PUT /api/v1/{tenant}/concurrency-limit` with the scope in the body, and page through search results. |
| [`SYSTEM_SETTINGS` and `TENANT_SETTINGS` removed](./settings-permissions-removed) (EE) | Role definitions in the API, `kestractl`, or Terraform | Remove both permissions. Requests that include them fail with a 422. Stored roles need no change. |
| [`USER: IMPERSONATE` removed](./impersonate-permission-removed) (EE) | Role definitions in the API, `kestractl`, or Terraform, and API clients that impersonate with the `X-Kestra-Impersonate` header | Remove the action from your roles. Requests that include it fail with a 422. Only Instance Owners can impersonate. |
| [Namespace binding scope](./namespace-binding-scope) (EE) | Roles bound to namespaces, and Terraform or API callers that create namespace bindings | A namespace binding can only grant namespace-level permissions. The upgrade moves existing namespace bindings of roles with tenant-level permissions to a `<Role name> (namespace)` copy, and requests that bind such a role to a namespace fail with a 422. |
| [Allowed Namespaces for internal storage URIs](./storage-uri-allowed-namespaces) (EE) | Flows that read, write, or delete another namespace's files by `kestra://` URI | Add the reading flow's namespace to the Allowed Namespaces of the namespace that owns the files. Tasks that reach a restricted namespace's files now fail. |
| [Namespace IDs with an empty segment](./namespace-id-empty-segment) | Namespaces whose ID ends with a dot or contains `..`, such as `team.` | Move their flows, namespace files, KV pairs, and role bindings to a valid namespace. Saving a flow in such a namespace fails, and its namespace files and KV store stop working. |
| [Server CLI commands deprecated](./server-cli-commands-deprecated) | Scripts that call `kestra flow`, `kestra namespace kv`, `kestra auths`, `kestra tenants`, or `kestra workers` commands | Move to the `kestractl` equivalents. Deprecated commands now print a deprecation line to stdout. |
| [Queue configuration keys](./queue-backend-configuration) (EE) | Kafka, Redis, and AMQP deployments | Move settings under `kestra.queue.<type>`. The old keys still work but log a deprecation warning. |
| [POST-only logout](./sso-logout-post-only) (EE) | SSO deployments, configurations with `get-allowed: true`, and direct links to `/logout` | Register `<your Kestra URL>/ui` as the post-logout redirect URI in your identity provider and remove `get-allowed` overrides. `GET /logout` now returns 405. |
| [Asset relations](./asset-relations) (EE) | Users of the lineage-events API, `kestractl assets lineage-events`, or `PurgeAssets` lineage options | Read lineage from the relations API instead. Flows with an invalid asset `id` are now rejected on save. |
| [Asset write timing](./asset-write-timing) (EE) | Tasks or flows that write the same declared asset concurrently, status filters on `active`, and API clients reading `assetEmits` | Expect `WARNING` on the task that finds the asset locked, include `pending` and `updating` in status filters, and read lineage from the relations API. |
| [dbt asset types](./dbt-asset-types) (EE) | Asset triggers, `AssetShipper` mappings, and declared inputs that match dbt assets on the `Table` type | Match on `DbtModel`, `DbtSeed`, or `DbtSnapshot` instead. Existing dbt assets are retyped on their next run. |
| [Webhook responses without `wait`](./webhook-response-without-wait) | Webhook triggers that set `responseCode` without `wait: true` | The immediate response now uses `responseCode`. If it reads `outputs`, set `wait: true` or remove it: otherwise the webhook responds with `500`. |
| [Flow output types](./flow-output-types) | Flow outputs typed `SELECT`, `MULTISELECT`, `EMAIL`, `FORM`, or `REUSABLE_INPUTS` | Change the type to `STRING`, or `ARRAY` for a list. Existing flows still run, but saving them fails until you do. |
