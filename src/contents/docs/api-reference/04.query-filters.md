Kestra list and bulk by-query endpoints accept structured filters via the `filters` query parameter. This page covers the syntax, available operators, and the fields each resource type supports.

## Syntax

Filters use bracket notation: `filters[<field>][<operator>]=<value>`.

```
GET /api/v1/main/executions/search?filters[namespace][EQUALS]=company.team
```

Pass multiple filters as separate query parameters:

```
GET /api/v1/main/executions/search?filters[namespace][EQUALS]=company.team&filters[state][IN]=CREATED,RUNNING
```

### AND / OR grouping

Logical groups use the same bracket notation as top-level filters, wrapped under `and[N]` or `or[N]`:

```
GET /api/v1/main/executions/search
  ?filters[and][0][namespace][EQUALS]=company.team
  &filters[and][1][state][IN]=CREATED,RUNNING
```

Use `or` instead of `and` for OR semantics:

```
GET /api/v1/main/flows/search
  ?filters[or][0][namespace][EQUALS]=company.docs
  &filters[or][1][namespace][EQUALS]=company.test
```

Ungrouped top-level filters are combined with AND.

## Operators

| Operator | Description |
|---|---|
| `EQUALS` | Exact match |
| `NOT_EQUALS` | Excludes exact match |
| `IN` | Matches any value in a comma-separated list: `filters[state][IN]=CREATED,RUNNING` |
| `NOT_IN` | Excludes all values in a comma-separated list |
| `CONTAINS` | Value contains the string |
| `NOT_CONTAINS` | Value does not contain the string |
| `STARTS_WITH` | Value starts with the string |
| `ENDS_WITH` | Value ends with the string |
| `PREFIX` | Dot-segment prefix match — `company` matches `company`, `company.team`, and `company.team.prod`, but `company.t` does **not** match `company.team`. Primarily useful on `namespace` and `flowId` fields that use dot notation. |
| `REGEX` | POSIX regular expression match |
| `GREATER_THAN` | Value is greater than (for dates and numbers) |
| `LESS_THAN` | Value is less than |
| `GREATER_THAN_OR_EQUAL_TO` | Value is greater than or equal to |
| `LESS_THAN_OR_EQUAL_TO` | Value is less than or equal to |
| `IS_NULL` | Field is absent or null (no value needed) |
| `IS_NOT_NULL` | Field is present and not null (no value needed) |

Not every operator applies to every field. The per-resource tables below list only the operators each field actually supports.

## Mutating by-query endpoints

Bulk endpoints (`DELETE`, `POST`, and `PUT` on `.../by-query` paths) require the `filters[...]` form. Flat legacy parameters such as `?namespace=x` are rejected with a `400 invalid-query-filters` error.

Read-only exports (`GET .../export/by-query`) are not subject to this restriction.

See [Invalid query filters](./03.problems/invalid-query-filters.md) for the full error reference and migration examples.
