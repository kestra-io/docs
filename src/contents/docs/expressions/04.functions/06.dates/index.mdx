Use these functions when you need to make scheduling or routing decisions based on the calendar — for example, skipping runs on weekends or public holidays.

## `isWeekend()`

Returns `true` if the date falls on Saturday or Sunday:

```twig
{{ isWeekend(trigger.date) }}
```

## `isPublicHoliday()`

Checks against a country's public holiday calendar. `countryCode` is an ISO 3166-1 alpha-2 code; `subDivision` is optional and accepts ISO 3166-2 codes:

```twig
{{ isPublicHoliday(trigger.date, 'US') }}
{{ isPublicHoliday(trigger.date, 'DE', 'DE-BY') }}
```

## `isDayWeekInMonth()`

Returns `true` if the date is the Nth occurrence of the given weekday in its month. `position` accepts `FIRST`, `SECOND`, `THIRD`, `FOURTH`, or `LAST`:

```twig
{{ isDayWeekInMonth(trigger.date, 'MONDAY', 'FIRST') }}
```

## `isLastWorkingDay()`

Returns `true` if the date is the last working day of its month. Working days default to Monday–Friday. An optional second argument overrides which days count as working days using a comma-separated list of uppercase day names:

```twig
{{ isLastWorkingDay(trigger.date) }}
{{ isLastWorkingDay(trigger.date, 'MONDAY,TUESDAY,WEDNESDAY,THURSDAY') }}
```

The `date` argument accepts any ISO 8601 date or datetime string. Combine with `isPublicHoliday()` if you also need to exclude public holidays.

## `isLastDayOfMonth()`

Returns `true` if the date is the last calendar day of its month. Weekends and leap days count, so the function returns `true` on Saturday, May 31 and on February 29 in a leap year:

```twig
{{ isLastDayOfMonth(trigger.date) }}
```

The `date` argument is required and accepts any ISO 8601 date or datetime string. The function checks the date as written and does not convert it to UTC. `trigger.date` follows the Schedule trigger's `timezone`, so use it rather than `execution.startDate`, which is a UTC instant and can fall on a different calendar day. For example, this task runs only on the last day of the month in the schedule's timezone:

```yaml
- id: month_end_report
  type: io.kestra.plugin.core.log.Log
  runIf: "{{ isLastDayOfMonth(trigger.date) }}"
  message: Running the month-end report
```

To schedule the whole flow on the last day of the month, use the `L` day-of-month value in the cron expression instead, for example `cron: "0 11 L * *"`.

## `dayOfWeek()`

Returns the uppercase day name such as `MONDAY`:

```twig
{{ dayOfWeek(trigger.date) }}
```

## `dayOfMonth()`

Returns the day of the month as an integer (1–31):

```twig
{{ dayOfMonth(trigger.date) }}
```

## `monthOfYear()`

Returns the month as an integer (1–12):

```twig
{{ monthOfYear(trigger.date) }}
```

## `hourOfDay()`

Returns the hour as an integer (0–23):

```twig
{{ hourOfDay(execution.startDate) }}
```

## `isDateBetween()`

:::badge{version=">=2.0.4" editions="OSS,EE,Cloud"}
:::

Returns `true` if the date is strictly after the first bound and strictly before the second:

```twig
{{ isDateBetween(trigger.date, '2025-12-31T23:59:59Z', '2026-06-30T23:59:59Z') }}
```

The values are compared as instants, so bounds written with different offsets still compare correctly. Give every value an explicit offset (`Z` or `±HH:MM`): a datetime without one raises an error.
